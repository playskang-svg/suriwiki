# 택소노미 기준과 동의어 사전

## 1. L1 space (공간)

| id | 라벨 | 포함 |
|---|---|---|
| `bath` | 욕실 | 화장실, 샤워실 |
| `kitchen` | 주방 | 싱크대, 후드, 상부장 |
| `entrance` | 현관·출입문 | 방화문, 현관문, 강화도어, 자동문 |
| `room` | 거실·방 | 방문, 벽지, 붙박이 가구 |
| `veranda` | 베란다·발코니 | 창호, 샤시, 베란다 바닥 |
| `store` | 상가·상업공간 | 큐비클, 비상구 방화문, 매장 출입문 |

**분류 기준**: 검색자가 "어디를 고치나"로 먼저 떠올리는 단위.
같은 대상이라도 공간이 다르면 다른 노드입니다(욕실 문틀 ≠ 방문).

## 2. L2 target (대상)

**기준**: 견적·시공 단위가 되는 물리적 대상.
"실리콘"처럼 재료가 곧 시공 단위인 경우 target으로 둡니다.
"ABS"처럼 재료 자체는 target이 아니라 `materials` 로 두고 CT3 WIKI 노드를 만듭니다.

## 3. L3 problem (문제·증상)

**기준**: 사용자가 눈으로 보고 말할 수 있는 증상.
전문 용어가 아닌 **사용자 언어**를 label로, 전문 용어는 `aliases` 로 둡니다.

```
label: "처짐·바닥 끌림"        ← 사용자 언어
aliases: ["도어 새깅", "힌지 처짐"]  ← 전문 용어
```

## 4. L4 intent (검색 의도)

| intent | 사용자가 실제로 치는 말 |
|---|---|
| `cause` | "왜", "원인", "이유", "자꾸" |
| `howto` | "방법", "셀프", "직접", "순서", "하는 법" |
| `spec` | "종류", "특징", "규격", "무슨 차이" (단일 대상) |
| `compare` | "vs", "비교", "어떤 게", "차이" |
| `judge` | "가능", "해야 하나", "기준", "시기" |
| `case` | "사례", "시공사례", "실제" |
| `cost` | "비용", "가격", "얼마" |
| `area` | 지역명 + 대상 |

## 5. 동의어 정규화 사전

중복 판정(`normalize()`)에서 사용합니다. 검색어를 표준형으로 바꾼 뒤 비교합니다.

### 공간

```
화장실 → 욕실
샤워실 → 욕실
싱크대 → 주방       (단, "싱크대 상판"은 target으로 유지)
현관 → 현관·출입문
발코니 → 베란다
```

### 대상

```
도어프레임, 문틀재, 문선 → 문틀
방문, 실내문, 목도어 → 방문·문짝
강화유리문, 유리문, 통유리문 → 강화도어
현관문, 세대현관문 → 방화문·현관문
인조대리석, 인조대리석상판 → 싱크대 상판
샤시, 새시, 창틀 → 창호
플로어힌지, 바닥힌지, 후로아힌지 → 플로어힌지
피벗힌지, 피봇힌지 → 피벗힌지
상롯트, 상부힌지, 어퍼힌지 → 상부힌지
도어체크, 도어클로저, 클로저 → 도어클로저
```

### 증상

```
부식, 삭음, 곰팡이썩음 → 썩음
새깅, 늘어짐, 주저앉음 → 처짐
끌림, 바닥긁힘, 문끌림 → 바닥 끌림
크랙, 금감, 갈라짐 → 크랙
들뜸, 뜸, 벌어짐 → 들뜸
탈락, 떨어짐 → 탈락
누수, 물샘, 물새는 → 누수
```

### 표현 정규화

```
- 조사 제거: 이/가/은/는/을/를/의/에/에서/으로/로
- 접미 제거: 하는법, 하는방법, 방법, 추천, 잘하는곳, 업체
- 공백·특수문자 제거
- 숫자 단위 통일: 12T = 12t = 12미리
```

## 6. 노드를 새로 만들 때 체크리스트

```
□ 기존 노드의 alias로 흡수 가능한가? (가능하면 새로 만들지 않는다)
□ 검색자가 이 말을 실제로 치는가? (전문 용어만이면 alias로)
□ 이 노드로 답할 질문이 1문장으로 써지는가?
□ intent가 기존 형제 노드와 겹치지 않는가?
□ 근거가 될 CASE가 있거나, 없으면 HOLD로 둘 준비가 됐는가?
□ area_expandable 이면 그 지역 CASE가 실제로 있는가?
```

## 7. 절대 하지 않는 것

- 검색량을 늘리려고 **없는 증상·대상**을 노드로 만들기
- 지역 목록을 기계적으로 곱해 노드 양산 (CASE 없으면 전부 HOLD)
- 하나의 노드에 여러 intent를 섞기 (페이지가 초점을 잃음)
- 구체적 월 검색량 수치를 지어내기 (`volume_hint` 3단계만 사용)
