# 06 · 입력 및 생성 화면

사용자는 같은 정보를 여러 번 입력하지 않고,
**현장 사실을 한 번 입력한 뒤 AI의 분석 결과를 확인**하는 방식이 가장 단순합니다.

| 화면 | 내용 | 담당 |
|---|---|---|
| 1. 기본정보 | 지역 / 건물·공간 / 수리 대상 | 사람 입력 |
| 2. 현장내용 | 문제 / 판단 / 실제 작업 / 결과·한계 | 사람 입력 |
| 3. 사진 | 전체 업로드 / 반드시 사용 / 공개 금지 | 사람 입력 + AI 분류 |
| 4. 추가정보 | 원인 / 재료 / 공구 / 상황 / 관리 / 시간 등 | 선택 입력 |
| 5. AI 분석 | 키워드 묶음 / LANDING 6~8개 후보 / CT / 모듈 / 이미지 세트 | AI 생성 |
| 6. 사람 확인 | 통합·분리 / 제외 / 꼭 공략할 키워드 추가 | 사람 승인 |
| 7. 생성·미리보기 | CASE 원고 + 선택 LANDING + WIKI/TOPIC 업데이트 제안 | AI 생성 → 사람 검수 |

## 추천 UX

> 키워드 입력창을 여러 개 만들지 말고 **AI가 먼저 키워드 묶음을 제안**합니다.
> 사용자는 **[한 페이지로 사용] / [별도 페이지로 분리] / [제외]** 만 선택하고,
> 필요할 때만 "꼭 공략할 키워드"를 추가합니다.

## 화면별 구현 사양

### 1. 기본정보

| 필드 | 타입 | 필수 | 비고 |
|---|---|---|---|
| `area_sido` / `area_sigungu` / `area_dong` | select | ✔ / ✔ / – | 행정구역 마스터 참조 |
| `building_type` | select | ✔ | 아파트 / 빌라 / 오피스텔 / 단독 / 상가 |
| `space` | select | ✔ | 욕실 / 주방 / 현관 / 베란다 / 거실 / 방 / 외부 |
| `target` | combobox | ✔ | 문틀 / 문짝 / 타일 / 실리콘 / 수전 / 배수구 / 창호 … |

### 2. 현장내용 (자유 서술 + 최소 글자수 없음)

| 필드 | 안내 문구 |
|---|---|
| `problem` | 무엇이 어떤 상태였나요? (썩음/들뜸/누수/깨짐…) |
| `judgement` | 무엇을 보고 작업 방향을 정했나요? |
| `work_steps` | 실제로 한 순서를 짧게 나열해 주세요 |
| `result` / `limit` | 작업 후 달라진 점 / 남은 한계 |

> **중요**: 문장을 다듬을 필요 없습니다. 사실만 적으면 AI가 모듈로 재구성합니다.

### 3. 사진

- 드래그&드롭 다중 업로드(최대 30장)
- 각 썸네일에 토글 2개: `반드시 사용` `공개 금지`
- 업로드 직후 AI가 role 자동 태깅 → 사람이 드롭다운으로 수정 가능
- pHash 유사도 0.92 이상이면 "유사 사진" 배지 표시

### 4. 추가정보 (전부 선택)

`cause` `materials[]` `tools[]` `situation` `maintenance` `duration` `safety_flags[]`

- `safety_flags` 에 `electric | gas | structure | severe_leak | height` 중 하나라도 켜지면 **M16 자동 필수**.

### 5. AI 분석 (결과 화면)

```
[키워드 묶음]  ── keyword-tree 스킬 결과
  ● 욕실 문틀 썩음 (원인)            우선순위 82   OPEN
  ● 문틀 부분수리 가능 여부           우선순위 76   OPEN
  ● 강남 문틀수리                    우선순위 71   OPEN (지역 CASE 있음)
  ○ 문틀 교체 비용                   우선순위 44   HOLD (금액 근거 없음)

[LANDING 후보 6~8개]
  각 후보 = 검색질문 1문장 + 추천 CT + 필수/옵션 모듈 + 이미지 세트 미리보기
```

### 6. 사람 확인

각 후보 카드에 3버튼만 노출: `한 페이지로 사용` `별도 페이지로 분리` `제외`
하단에 "꼭 공략할 키워드" 입력창 1개(선택).

### 7. 생성·미리보기

- 좌: 모듈 순서 리스트(드래그로 순서 변경 가능)
- 우: 실제 페이지 렌더 미리보기
- 각 모듈 블록에 **근거 배지**(어느 CASE 필드/사진에서 나왔는지) 표시
- 근거 없는 모듈은 빨간 배지 + 발행 차단
