# 16 · 품질 게이트 · 사실성·브랜드 규칙

이 문서는 **발행을 막는 규칙**입니다. 권고가 아니라 차단 조건입니다.

---

## 1. 사실성 규칙 (절대)

| # | 규칙 | 위반 시 |
|---|---|---|
| F1 | 실제 CASE에 없는 **지역**을 쓰지 않는다 | HOLD |
| F2 | 근거 없는 **금액·기간**을 단정하지 않는다. M14는 "달라지는 이유"만 | 해당 문장 삭제 또는 HOLD |
| F3 | **후기·평점·시공건수**를 생성하지 않는다 | 해당 블록 삭제 |
| F4 | CASE에 없는 **공정·재료·공구·결과**를 쓰지 않는다 | HOLD |
| F5 | 사진의 **실제 내용을 변경**하지 않는다 (없던 손상/공정/결과 합성 금지) | 이미지 폐기 |
| F6 | `is_private = true` 사진은 어떤 페이지에도 쓰지 않는다 | 빌드 실패 |
| F7 | 자격·면허·인증을 보유 사실 없이 표기하지 않는다 | 해당 문구 삭제 |

> Stitch 디자인의 `10,000+`, `4.9`, `99% 조색 일치율` 은 **더미값**입니다.
> 실측 근거가 없으면 StatStrip을 렌더하지 않습니다. (F3)

## 2. 구조 규칙

| # | 규칙 | 검사 |
|---|---|---|
| S1 | 중심 CT 1개 | `count(content_type) == 1` |
| S2 | 필수 모듈 전부 존재 + 근거 있음 | `required ⊆ order ∧ ∀m evidence(m)≠∅` |
| S3 | 옵션 모듈 2~4개 | `2 ≤ |selected| ≤ 4` |
| S4 | 위험 플래그 → M16 포함 | `any(safety_flags) → M16 ∈ order` |
| S5 | 지역 언급 → 해당 지역 CASE 보유 + M23 | F1 연동 |
| S6 | CT6 → M08.steps == case.work_steps | 1:1 대응 |
| S7 | CT4 → 비교 대상 2개 이상 | `|M13.items| ≥ 2` |
| S8 | CT1 → case.cause 존재 | 없으면 CT5 전환 또는 HOLD |

## 3. 중복 규칙

| # | 규칙 | 임계값 |
|---|---|---|
| D1 | dedupe_key 충돌 없음 | 완전일치 → MERGE |
| D2 | 같은 CASE 파생 페이지 간 diff_score | ≥ 0.45 |
| D3 | 같은 CT 다른 페이지와 모듈 순서 유사도 | < 0.85 |
| D4 | FAQ 질문 유사도 | < 0.85 |
| D5 | 이미지 세트 Jaccard | < 0.6 |
| D6 | CTA 문구 | 그룹당 3종 이상 로테이션 |

## 4. 링크·SEO 규칙

| # | 규칙 |
|---|---|
| L1 | 내부링크 3~8개, 전부 실재 URL (404 링크 → 빌드 실패) |
| L2 | 고아 페이지 금지 — 상위 TOPIC/AREA에서 링크됨 |
| L3 | title 30~45자, description 70~120자 |
| L4 | h1 1개 |
| L5 | 모든 이미지 alt 존재 |
| L6 | FAQPage JSON-LD는 화면에 실제 보이는 Q&A만 |
| L7 | `AggregateRating`/`Review` 마크업은 실제 후기 있을 때만 |

## 5. 브랜드·표현 규칙

**권장 표현**

- "상태에 따라 다릅니다", "현장 확인 후 판단합니다"
- "이 사례에서는 ~했습니다" (일반화 대신 사례 한정)
- "사진을 보내주시면 먼저 확인해 드립니다"

**금지 표현**

| 금지 | 이유 | 대체 |
|---|---|---|
| "100% 완벽 복원", "무조건", "절대" | 단정·과장 | "대부분의 경우", "이 사례에서는" |
| "업계 1위", "최저가", "국내 유일" | 근거 없는 최상급 | 삭제 |
| "누구나 쉽게 셀프로" (전기·구조·고소) | 안전 | M16 안전 배너 + 전문가 권고 |
| "○○만원에 해결" (근거 없음) | F2 | "비용이 달라지는 이유: …" |
| 타 업체 실명 비방 | 법적 위험 | 삭제 |

## 6. CTA 규칙

- 페이지 그룹별 3종 이상 로테이션 (D6)
- LANDING은 `photo_upload` 우선 (사진 상담이 전환·정확도 모두 유리)
- 모든 CTA는 **다음 행동 1개**만 강조. 버튼 3개 나열 금지.

예시 로테이션:

```
A. "수리가 필요한 곳 사진 한 장만 보내주세요"
B. "전체 사진과 근접 사진을 함께 보내주시면 더 정확합니다"
C. "지금 상태를 사진으로 보내주시면 가능 여부를 먼저 알려드립니다"
```

## 7. 판정 매트릭스

| 조건 | decision |
|---|---|
| 모든 게이트 통과 + 유사 페이지 없음 | **CREATE** |
| 같은 질문 페이지 존재 + 새 CASE 근거 추가됨 | **UPDATE** |
| dedupe_key 일치 또는 diff_score < 0.25 | **MERGE** |
| F1~F7 중 위반 / S2 위반 / 지역 CASE 없음 | **HOLD** |

`HOLD` 는 실패가 아닙니다. **필요한 근거 목록**을 함께 출력해 현장팀이 채우게 합니다.

```
HOLD: /repair/seocho-doorframe
  필요: 서초구 문틀 CASE 1건 이상 (사진 BEFORE/AFTER 포함)
  대안: 노드를 bath.doorframe.rot#judge 로 MERGE
```

## 8. CI 검사 (배포 전 자동)

```bash
npm run gate:facts     # F1~F7
npm run gate:structure # S1~S8
npm run gate:dedupe    # D1~D6
npm run gate:links     # L1~L7
```

하나라도 실패하면 배포 중단.
