# 09 · 한 CASE에서 다른 콘텐츠를 만드는 예시

**원천 CASE:** 강남 아파트 욕실 문틀 하부 부식 교체

| 페이지 후보 | Page Type | CT | Module 순서 예시 | 차별화 중심 |
|---|---|---|---|---|
| 강남 썩은 문틀 수리 | LANDING | CT1 문제·해결형 | M01 → M03 → M04 → M05 → M09 → M19 → M20 → M24 | 부식 **원인과 해결방법** 중심 |
| 문틀 부분수리와 교체 기준 | LANDING/WIKI | CT4 비교·선택형 | M01 → M07 → M13 → M06 → M19 → M20 → M21 | **부분수리와 교체 비교** 중심 |
| 강남 욕실 문틀 하부 교체 사례 | CASE | CT6 사례·현장형 | M02 → M03 → M06 → M08 → M18 → M20 → M24 | **실제 판단·공정·결과** 중심 |

## 핵심

> 같은 CASE를 사용해도 **제목만 바꾸는 것이 아니라 검색 질문에 맞춰 CT·모듈·사진 세트를 바꿉니다.**
> 이것이 대량 LANDING 생성 시 중복과 저품질 위험을 줄이는 기본 장치입니다.

## 확장 예시 — 같은 CASE에서 6개 페이지

| # | 검색 질문 (search_intent) | Page Type | CT | 핵심 모듈 | 이미지 초점 |
|---|---|---|---|---|---|
| 1 | 욕실 문틀은 왜 아래쪽부터 썩나요? | LANDING | CT1 | M01·M03·M04·M09 | BEFORE 근접 + 원인 화살표 |
| 2 | 썩은 문틀, 하부만 수리할 수 있나요? | LANDING | CT5 | M01·M03·M05·M06·M07 | DETAIL + 손상범위 박스 |
| 3 | 문틀 부분수리와 전체교체 중 뭘 해야 하나요? | WIKI | CT4 | M01·M13·M07·M14 | 비교 콜라주 |
| 4 | 강남 욕실 문틀 하부 교체 사례 | CASE | CT6 | M02·M03·M06·M08·M18·M20 | BEFORE→PROCESS→AFTER 전 공정 |
| 5 | ABS 문틀은 어떤 자재인가요? | WIKI | CT3 | M01·M11·M13 | MATERIAL 근접 |
| 6 | 강남 문틀수리 | AREA/LANDING | CT6 | M01·M23·M19·M20·M24 | AFTER 대표컷 + 지역 CASE |

### 차별화 검증표 (R8 적용)

각 페이지의 **핵심 모듈 집합**과 **원본 이미지 집합**은 아래와 같다고 둡니다.
(Jaccard는 여기서 결정론적으로 계산되며, 질문·첫 답변 유사도는 임베딩 모델에 따라 달라지므로 값을 명시합니다.)

| 페이지 | 핵심 모듈 | 원본 이미지 |
|---|---|---|
| P1 원인 (CT1) | M01 M03 M04 M09 M19 M20 | i1 i2 i3 i7 |
| P2 판단 (CT5) | M01 M03 M05 M06 M07 M19 M20 | i2 i4 i5 i9 |
| P3 비교 (CT4) | M01 M07 M13 M14 M19 M20 | i3 i5 i10 i11 |
| P4 사례 (CT6) | M02 M03 M06 M08 M18 M20 | i1 i2 i4 i6 i8 i12 |
| P5 자재 (CT3) | M01 M11 M13 M19 | i13 i14 |
| P6 지역 (CT6/AREA) | M01 M19 M20 M23 M24 | i6 i8 i15 |
| P2′ 중복후보 | M01 M03 M05 M06 M07 M19 M20 | i2 i4 i5 i16 |

`diff_score = 0.30·(1−sim질문) + 0.25·(1−sim첫답변) + 0.25·(1−J모듈) + 0.20·(1−J이미지)`

| 비교쌍 | sim 질문 | sim 첫 답변 | J 모듈 | J 이미지 | diff_score | 판정 |
|---|---|---|---|---|---|---|
| P1 vs P2 | 0.41 | 0.22 | 0.44 | 0.14 | **0.68** | CREATE |
| P2 vs P3 | 0.38 | 0.25 | 0.44 | 0.14 | **0.68** | CREATE |
| P1 vs P4 | 0.33 | 0.30 | 0.20 | 0.25 | **0.73** | CREATE |
| P3 vs P5 | 0.31 | 0.28 | 0.43 | 0.00 | **0.73** | CREATE |
| P1 vs P6 | 0.19 | 0.14 | 0.38 | 0.00 | **0.81** | CREATE |
| P2 vs P2′ | 0.97 | 0.95 | 1.00 | 0.60 | **0.10** | **MERGE** |

> **구현 시**: 이 표를 손으로 옮기지 말고 [`data/difftest.fixtures.json`](../data/difftest.fixtures.json) 을 읽어
> 테스트하세요. 모듈·이미지 Jaccard는 `pages` 정의에서 계산해 `jaccard_*` 값과 일치하는지까지 검증합니다.
> **기대값이 안 맞는다고 테스트를 `expect(true).toBe(true)` 로 통과시키지 마세요.**
> 계산이 안 맞으면 구현이나 픽스처 중 하나가 틀린 것이므로 보고해야 합니다.

## 반례 — 이렇게 만들면 안 됨

❌ **제목만 바꾼 양산**

```
강남 문틀수리 / 서초 문틀수리 / 송파 문틀수리 …
  → 본문·사진·FAQ·CTA 동일, 지역명만 치환
  → 지역 CASE 없음 → 전부 HOLD
```

✅ **올바른 지역 확장**

```
강남 문틀수리   ← 강남 CASE 3건 보유, 실제 사진·판단 인용 (CREATE)
서초 문틀수리   ← 서초 CASE 0건 → HOLD, 노드 status = HOLD 로 대기
```

❌ **FAQ 복붙**

```
모든 페이지 하단에 동일한 FAQ 5개 → R7 위반 → 빌드 실패
```
